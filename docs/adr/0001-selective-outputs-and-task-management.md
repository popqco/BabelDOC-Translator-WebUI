# 0001. 可选 PDF 产物与任务解耦决策 (ADR)

- **状态**：已批准 (Approved)
- **决策者**：用户 & Codex
- **日期**：2026-09-18

## 背景
用户反馈原桌面工具默认强制输出 mono、dual 和全量 ZIP 压缩包，导致输出目录臃肿，且缺乏针对单次批量任务的精细管理（如运行中追加、按需重试失败文件、单文档取消等）。

## 决策要点
1. **生成控制下沉至内核**：在调用 BabelDOC 0.6.4 时，通过 `--no-mono` 和 `--no-dual` 参数在底层阻止不需要的 PDF 生成，杜绝无意义磁盘占用。
2. **输出交付模式分流**：
   - 默认仅输出双语对照版 (`dual`)。
   - 增加 ZIP 打包开关，默认为关闭；开启时支持“PDF + ZIP 并存”与“仅保留 ZIP”两种策略。
   - “仅保留 ZIP”采用安全两步提交：创建临时 ZIP -> 校验条目与哈希 -> 重命名正式包 -> 清理独立 PDF。
3. **架构解耦为任务状态机**：新增 `core/task_manager.py`，管理运行态任务队列、进程生命周期（基于 Windows Job Object）及历史记录持久化。

## 影响与权衡
- 彻底解决磁盘空间浪费与多余输出的困扰。
- UI 交互层不再直接运行长时间阻塞的子进程，显著提高界面响应度与容错性。
